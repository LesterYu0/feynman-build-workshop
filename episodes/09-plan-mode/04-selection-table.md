# ④ 三种规划架构选型决策表（造物工坊 #C09）

> 别追新，追匹配。先判断任务的可预测性、步骤数、成本敏感度、工具依赖，再选架构。

| 维度 | Plan-and-Execute | ReWOO | LLMCompiler |
| --- | --- | --- | --- |
| 核心机制 | Planner 出完整步骤 → Executor 跑 → Replanner 兜底 | 一次规划，步骤间变量传值 `#E1=#E2` | 生成任务 DAG，并行执行 |
| 模型调用次数 | 每步一次（中等） | **仅 1 次**（最省 token） | 调度 + 多分支（多） |
| 并行能力 | 弱 | 无 | **强（DAG 并行）** |
| 成本 | 中等 | **最低（省近一半 token）** | 高（调度开销大） |
| 调试难度 | 低 | 中（变量传值易错） | **高（出错难定位）** |
| 心智负担 | 低 | 中 | **最高** |
| 适用场景 | 多步、可预测、成本敏感 | 多步检索、成本极敏感 | 工具密集、依赖清晰 |

## 硬规则（钉死）
- `< 3 步` 或 `高度动态` → 直接用 **ReAct**，别上 Plan
- `多步 + 成本敏感` → **Plan-and-Execute** 或 **ReWOO**
- `工具密集 + 依赖清晰` → **LLMCompiler** 吃满并行红利（重型武器，慎用）

## 本期主线
手写最小版用 **Plan-and-Execute**（零件最透明），最后用 **LangGraph** 落地版对照框架替你管了什么。

## 真实数据
ReWOO 用于多步检索任务，token 比 Plan-and-Execute **省近一半**（少了一轮轮模型调用）。
