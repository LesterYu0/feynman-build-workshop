# ⑤ Replan 三级触发树（造物工坊 #C09）

> 核心原则：**Replan 是兜底，不是默认动作。** 把它当急救包，别当日常操作。
> 每一次 Replan = 一次完整重新推理，烧整段 token 和时间。能 Retry 兜住的，绝不要 Replan。

```
观察到一个失败 / 异常
│
├─ ① Retry（瞬时错误）
│     典型：超时、网络抖动、限流
│     动作：同计划原地重试，次数受「步骤数上限」约束
│     成本：极低（一次调用）
│     ✅ 本期实拍：步骤3瞬时超时，Retry 成功兜住，replan=0
│
├─ ② Fallback（确定性问题）
│     典型：某工具挂了 / 某路径不通 / 已知替代方案
│     动作：换一条确定性替代路径，不重规划全盘
│     成本：低（一次调用 + 局部切换）
│
└─ ③ Replan（矛盾性观察）
      典型：计划本身有逻辑矛盾 / 目标已变 / 环境已过期
      动作：Replanner 根据已发生的状态调出全新计划
      成本：高（整段重新推理）
      底线：死循环防护必须就位（见下）
```

## 死循环防护四件套（Replan 的底线）
1. **步骤数上限**：总步骤封顶
2. **replan 预算**：replan 次数封顶
3. **进度检测**：连续 N 步无进展即熔断
4. **语义去重**：相同(状态,动作)不再重复执行

> 任何一条没设，线上就是半夜叫醒你的事故。
