# Agent记忆系统 5信号诊断清单

> 截图保存，下次翻车翻出来排查。

---

## 信号1 · 文件膨胀
| 项目 | 说明 |
|:---|:---|
| 症状 | 记忆文件随步数线性增长，跑1000步后MB级 |
| 指标 | 每步新增字符数 > 50 |
| 根因 | 无界追加，重复条目无限累积 |
| 解法 | 引入UPSERT/去重操作；定期归档/摘要 |
| AutoMem数据 | 地图文件从138字符/步 → 6字符/步（-95%） |

---

## 信号2 · 写了不查
| 项目 | 说明 |
|:---|:---|
| 症状 | Agent写记忆很勤快，但关键决策前从不读 |
| 指标 | Write/Search比 > 0.6 |
| 根因 | Base模型没学过"先查后写" |
| 解法 | LoRA微调记忆能力；在prompt里强制"决策前read" |
| AutoMem数据 | Write/Search比 0.84 → 0.39（-54%） |

---

## 信号3 · 策略僵化
| 项目 | 说明 |
|:---|:---|
| 症状 | 换一个任务类型，记忆模板就失效 |
| 指标 | 同一套prompt在3个以上任务场景表现差异 > 30% |
| 根因 | 记忆策略写死在prompt里，无法随任务演化 |
| 解法 | meta-LLM审查完整轨迹，自动迭代scaffold |
| AutoMem做法 | Loop1：meta-LLM生成v(N+1) scaffold |

---

## 信号4 · 上下文溢出
| 项目 | 说明 |
|:---|:---|
| 症状 | 记忆文件太大，挤占任务推理空间 |
| 指标 | 每次推理时记忆token占比 > 40% |
| 根因 | 记忆不经检索全部塞进上下文 |
| 解法 | 记忆动作按需检索；分层存储（摘要+原始） |
| AutoMem数据 | 每步上下文缩减25% |

---

## 信号5 · 延迟后果
| 项目 | 说明 |
|:---|:---|
| 症状 | 第50步漏记，第800步才翻车 |
| 指标 | 错误决策与最早缺失记忆间隔 > 100步 |
| 根因 | 人无法审查10^4-10^5步的完整轨迹 |
| 解法 | meta-LLM全轨迹审查 + 门控机制 |
| AutoMem做法 | Loop1用meta-LLM做episode-level审查 |

---

## 一句话总结

> 给Agent加记忆文件只是起点。让Agent学会管理记忆，才是从"能记"到"会用"的跨越。
