## 三、3 个"文档没写但你一定会遇到"的坑（护城河 · 第四层）

这些不是从文档推出来的，是**真写代码跑 demo 时撞到的**：

| # | 坑 | 真实现象 | 解法 |
|---|----|---------|------|
| **坑① 一家卡死拖垮全队** | 不给 ensemble 设整体超时，一个 provider 卡住，你会永远等下去 | demo 里 Kimi 模拟超时，`as_completed` 若无 timeout 直接挂 | 给 `as_completed(timeout=...)` 设整体超时，超时的自动降级 |
| **坑② 空提案污染投票** | 失败/空返回的 provider 也进了聚合，把共识拉偏 | 挂掉的 Kimi 返回 `[FAILED]`，不过滤就会参与投票 | 聚合前过滤 `ok=False` 和空文本 |
| **坑③ 投票不归一化，共识永远不成立** | `"Yes"` / `"yes."` / `" YES"` 被当成 3 个不同答案，多数投票永远选不出 | 三家给的是同一答案但标点/大小写不同 | 投票前 `strip().lower().rstrip(标点)` 归一化 |
| **坑④（加餐）难度判断悖论** | 为了省钱先调一次大模型判断"这题难不难"——结果判断本身就烧掉了省下的钱 | — | 用长度+关键词的**廉价规则**判难度，绝不再调大模型 |
| **坑⑤（加餐）ensemble ≠ 无脑全调** | 简单题也组队 = 成本翻 N 倍，省钱路由变烧钱路由 | 简单题"中国首都"若组队，成本从 0.0002 涨到 0.012 | Router 先判难度，只有难题才组队 |

标题承诺锁定 **坑①③⑤** 这 3 个最反直觉的。

## 六、标题候选

> **标题手法：采用「意外组合」式（对标 EP.43 加油站×大模型）。** 用一个机理可桥接、但表面不搭界的日常物件制造好奇心缺口——这里选 **「拼团」**：多模型合算 ⇒ 多人拼团，既对应 ensemble（组团），又对应砍 token（拼团省钱），且「单挑打不过、组团赢」反差天然成立。

1. `国产模型拼了个团：4家弱模型组团，咬住旗舰还省八成token + 100行可跑代码｜造物工坊 #08`（主推·意外组合）
2. `100行手写多模型Harness：国产模型组队打赢旗舰，但这3个坑文档全没写｜造物工坊 #08`
3. `别再把钱全砸给最贵的模型：手写ensemble routing，3个坑+省80%token｜造物工坊 #08`
4. `4个国产模型拼团怎么超过Fable5？我手搓了一遍，撞到3个文档没写的坑｜造物工坊 #08`

**主推 1**：意外组合开场（拼团×大模型）+ 反差钩子（弱模型组团咬住旗舰）+ 数据冲击（省八成token）+ 资产承诺（100行可跑代码）四要素齐全，与 EP.43 一脉相承。
